1. Resumen ejecutivo

Qué es: un sitio web seguro, de costo cero, que reemplaza los sistemas de Apps Script de visitas/tareas y de SOS/SOE. Mide a cada mercaderista con un puntaje (20 % visitas, 30 % tareas, 30 % tareas de frío, 10 % SOS, 10 % SOE) y permite justificar lo no efectivo con control y trazabilidad.
  • Una sola fuente de verdad: los reportes se cargan una vez y todos ven la misma información según su alcance.
  • Seguridad por perfil: cada persona ve solo lo suyo; el control está en la base de datos, no solo en la pantalla.
  • Trazabilidad: todo cambio queda en el historial con quién, cuándo y qué.
  • Sin correos: los usuarios ingresan con un código (admin, ecm035…).

2. Roles y responsabilidades

RolAlcance de datosResponsabilidad principal
AdministradorTodoCargar bases, crear usuarios y permisos, configuración, accesos. Único que carga datos nuevos.
GerenciaTodo (solo lectura); en «Datos» solo ve Equipo ECMAnalizar, auditar y decidir. No carga bases.
SupervisorSu equipo (todos si no tiene nombre asignado), opcionalmente limitado por regionesJustificar, gestionar pendientes y revisar a su equipo.
MercaderistaSolo sus datosEjecutar y justificar.

Se pueden crear tipos intermedios (por ejemplo «Analista de región») con permisos pantalla por pantalla.

PARTE 1 · Gerencia

Lectura, análisis y control. Gerencia no modifica datos operativos ni carga bases.

4. Cómo leer el desempeño

  1. Dashboard: elige el mes. Identifica los componentes bajo meta (rojo) a nivel total, luego por supervisor.
  2. Ranking en Visitas y Tareas: ordena equipos y ECM. Busca quién arrastra el resultado.
  3. Informe de motivos: qué porcentaje de lo no efectivo se justifica y con qué responsable. Si pesa mucho «CN», hay un problema de proceso, no de personas.
  4. Reincidencias: clientes con fallas repetidas; sugiere acciones de ruta o de relación comercial.
  5. Proyección e Insights: hacia dónde va el mes y qué recomienda el análisis automático.
  6. SOS y SOE → Resumen semanal: compara la semana con la anterior, mira PDV bajo meta y espacios ganados.
Ojo con la efectividad ajustada: solo cuenta los motivos ya asignados. Si hay muchos pendientes sin justificar, el resultado real puede ser mejor al mostrado; la auditoría indica el porcentaje de avance.

5. Auditoría y control

  • Para revisar: justificaciones con banderas (observaciones repetidas, sin evidencia, responsable CN dominante, antigüedad). Se aprueban o rectifican.
  • Observaciones repetidas: el mismo texto usado muchas veces suele indicar justificación genérica.
  • Cruce antifraude (Visitas): contrasta la visita con las evidencias y enlaces de Involves.
  • Historial de cambios: quién cambió qué y cuándo, en lenguaje claro. Filtra por «Dónde» y «Qué se hizo».
  • Avance por supervisor: qué supervisores mantienen sus pendientes al día.

6. Reportes para reuniones

  • Cada tabla se exporta a Excel, PNG y PDF; Visitas y Tareas también a PowerPoint.
  • El Informe mensual está listo para presentar.
  • El Resumen semanal de SOS y SOE se puede copiar o imprimir.
  • Las exportaciones respetan los filtros: ajusta fechas y supervisor antes de descargar.

PARTE 2 · Administración

Operación diaria de la plataforma. Solo el administrador ve los menús de Datos (cargas, catálogo) y Sistema.

8. Cargar las bases

Menú Datos → Cargar bases. Se pueden seleccionar varios archivos a la vez; cada uno se reconoce por sus encabezados y se muestra en la lista antes de subirlo (puedes quitar los que no quieras).

ArchivoSe reconoce porAlimenta
VisitasVISIT_DATEVisitas
TareasEstado_TareaTareas
RuteroCliente SAP + Nombre clienteRutero
Equipo ECMECM + TeléfonoMercaderistas
Encuestas SOS/SOEDescripción pregunta + Respuesta + Código clienteSOS y SOE
Espacios ganados / enlacesPerfil del PDV + EmpleadoEspacios ganados y enlaces
MetasEncabezados de metasMetas

Modos (visitas y tareas)

  • Actualizar: agrega nuevo y actualiza lo cambiado, sin borrar. Es el modo normal.
  • Reemplazar rango: borra y recarga las fechas del archivo (para corregir un período).
  • Reemplazar todo: deja solo lo del archivo (cuidado: borra el resto).
Orden recomendado la primera vez: Equipo ECM → Rutero → Visitas → Tareas → Encuestas → Espacios ganados → Metas. Luego, en Pesos, metas y configuración, pulsa Recalcular (tareas de frío).

Cómo leer el resultado

Al terminar verás: nuevas · actualizadas · sin cambios · omitidas. «Omitidas» son filas sin fecha, cliente o ECM. Si falla, un panel de error permanece en pantalla con la explicación (no desaparece solo).

Archivos CSV: las fechas se leen como día/mes/año. Archivos .xlsx muy grandes (más de 12 MB) se procesan por bloques con barra de progreso; no cierres la pestaña hasta que termine.

9. Usuarios

Menú Sistema → Usuarios.

  1. Pulsa Nuevo usuario.
  2. Escribe el código (letras, números, punto, guion; por ejemplo ecm035) y el nombre.
  3. Elige el tipo de usuario.
  4. Para mercaderistas: código ECM/BDR. Para supervisores: el nombre como viene en las bases; si lo dejas vacío, ve todos los equipos. Marca las regiones si deben limitarse.
  5. Define la contraseña inicial y entrégala por un canal seguro; pide cambiarla en el primer ingreso.
  • Cambiar clave: desde la fila del usuario.
  • Desactivar: el usuario deja de entrar y conserva su historial.
El código del mercaderista debe coincidir con el de las bases (ECM035). Si no coincide, esa persona no verá sus datos.

10. Tipos de usuario y permisos

Menú Sistema → Tipos de usuario y permisos. Hay una matriz con una columna por tipo.

  • Ver: pantallas y, dentro de cada una, pestañas (por ejemplo «Visitas → Cruce antifraude»).
  • Editar (capacidades): Cargar bases, Equipo ECM, Catálogo de marcas, Metas, Justificar, Revisar justificaciones, Corregir SOS/SOE, Espacios ganados.
  1. Crea un tipo nuevo o ajusta uno existente.
  2. Marca lo que puede ver y lo que puede editar.
  3. Guarda y asigna ese tipo a los usuarios.
Regla fija: la carga de bases es exclusiva del administrador, aunque se marque la capacidad para otro tipo. El tipo base (admin, gerencia, supervisor, asesor) define el alcance de datos y no se cambia con los permisos.

11. Pesos, metas y configuración

Menú Sistema → Pesos, metas y configuración:

SecciónQué controla
Pesos del puntaje20/30/30/10/10 por defecto; deben sumar 100.
Metas por defectoVisitas, tareas, frío, SOS y SOE; se usan solo si no existe meta personalizada del período.
Semana y exclusionesDía de inicio de semana (miércoles) y PDV excluidos de SOS/SOE.
Tareas de equipo de fríoExpresión que identifica esas tareas (COOLER, ESPACIO FRÍO, NEVERA). Muestra una vista previa y valida la expresión.
Otros ajustesFallas para considerar reincidente, duración mínima de visita (2 min), título de la plataforma.
Tras cambiar la expresión de frío o cargar tareas nuevas, pulsa Recalcular para reclasificar.

Metas personalizadas: en Metas y alcance se crean metas por semana o mes, por región o ECM, con modo y valor; tienen prioridad sobre las metas por defecto.

12. Motivos, catálogo y equipo ECM

  • Catálogo de motivos: cada motivo tiene responsable. CN no penaliza; cualquier otro (por ejemplo SGF) sí. Se pueden activar, desactivar y crear.
  • Catálogo de marcas: clasifica cada pregunta de encuesta en grupo (CN, competencia, EXCLUIR), tipo (PERCHA, RUMA, BANDEJA FRÍO, BANDEJA SECO), marca y producto. Las preguntas nuevas se clasifican solas; revisa las que quedan sin clasificar. Cambiar una clasificación afecta a todo SOS/SOE.
  • Equipo ECM: supervisor, región y teléfono de cada mercaderista. Mantenerlo al día evita datos «sin supervisor».

13. Accesos y movimiento

Menú Sistema → Accesos y movimiento (24 horas, 3 o 7 días):

  • Resumen por usuario: último acceso, accesos, días activos, pantallas y cambios; indica quién no ha entrado.
  • Accesos: cada ingreso, sesión retomada y pantalla visitada, con dispositivo.
  • Movimiento: cambios hechos (motivos, cargas, configuración, usuarios) con quién y cuándo.

Úsalo para detectar usuarios inactivos, accesos a horas inusuales o cambios masivos no esperados. Los accesos se registran desde la publicación de esta función.

14. Cierre de mes

  1. Verifica que visitas y tareas del mes estén completas (fecha «Datos hasta…»).
  2. Carga las últimas encuestas y espacios ganados.
  3. Pide a supervisores cerrar pendientes; revisa Avance por supervisor en Auditoría.
  4. Revisa la cola Para revisar y aprueba o rectifica.
  5. Pulsa Recalcular (frío) si cambiaste la configuración.
  6. Descarga el Informe mensual y el PowerPoint.
  7. Define las metas del mes siguiente.

Continuidad: si la única persona con acceso a GitHub o Supabase se ausenta, nadie podrá publicar cambios ni recuperar la base. Documenta quién más tiene acceso.

17. Seguridad y qué es público

  • Es público: el código del sitio (el repositorio es público para poder usar GitHub Pages gratis), la dirección de Supabase y una clave «anon» pública por diseño.
  • No es público: los datos. Sin iniciar sesión, la base no entrega ninguna fila. Cada perfil ve solo lo permitido por reglas en la propia base (RLS).
  • Contraseñas: las gestiona Supabase; nunca se guardan en el sitio. La clave de servicio (poderosa) vive solo en el servidor.
  • Fotos: almacén privado; se ven con enlaces temporales.
  • Trazabilidad: historial automático de cambios y registro de accesos.
  • Registro abierto desactivado: nadie puede crearse una cuenta; solo el administrador crea usuarios.
Pendiente recomendado: activar en Supabase (Authentication → Policies) la protección contra contraseñas filtradas. Si se quiere ocultar también el código, el repositorio puede hacerse privado y publicar con Cloudflare Pages.

18. Respaldo y continuidad

  • Código: está respaldado en GitHub (historial completo de versiones).
  • Datos: el plan gratuito de Supabase no garantiza respaldos diarios descargables. Recomendado: una vez al mes exportar las tablas clave (Supabase → Table Editor → Export) y guardar los archivos originales de cada carga, que permiten reconstruir visitas, tareas y encuestas.
  • Esquema: versionar las migraciones del proyecto con supabase db pull (ver Manual técnico).
  • Datos de configuración (metas, motivos, permisos, catálogo): se pueden exportar desde sus pantallas o la base.

19. Costos y límites

ServicioPlanLímites a vigilar
GitHub PagesGratis (repositorio público)Tamaño del sitio y tráfico mensual (amplios para este uso).
SupabaseGratis500 MB de base de datos, almacenamiento de fotos, ancho de banda; los proyectos inactivos se pausan tras un período sin uso.

Las tablas que más crecen son SOS/SOE (share_detalle) y el historial (bitacora). Si se acerca el límite, se pueden archivar meses antiguos o pasar a un plan de pago.

20. Publicar cambios

  1. Los cambios al código se suben al repositorio en GitHub (rama main).
  2. GitHub Actions publica el sitio automáticamente en 1–2 minutos.
  3. Los usuarios deben recargar con Ctrl + F5 para ver la nueva versión.

Los cambios en la base de datos se hacen como migraciones (nunca editando a mano en producción). Antes de publicar un cambio, el equipo técnico corre las pruebas automáticas (npm test), que no tocan datos reales.

21. Problemas y soluciones

SíntomaQué hacer
Nadie puede ingresarEn Supabase: Authentication → Sign In / Providers → Email debe estar habilitado (con «Allow new users to sign up» y «Confirm email» apagados).
Un usuario ingresa pero no ve nadaRevisar que esté activo, que su tipo tenga permisos y que su código ECM/supervisor coincida con las bases.
Una carga dice «no hay filas válidas»Usar el reporte original sin cambiar encabezados; comprobar que tenga fechas, clientes y ECM.
Fechas de SOS/SOE en meses equivocadosEra un problema de lectura de CSV (día/mes); ya está corregido. Si apareciera en datos viejos, pedir corrección por SQL al equipo técnico.
La plataforma no abre o no respondeEntrar a Supabase y comprobar que el proyecto no esté pausado; reactivarlo si lo está.
El sitio no se actualiza tras un cambioRevisar GitHub → Actions; si falló, volver a ejecutar el flujo. Recargar con Ctrl + F5.
Pantallas lentasReducir el rango de fechas; revisar Supabase → Advisors y Logs.
